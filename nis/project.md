# Описание проекта

[Задание P14-B](https://distsys.ru/osukhoroslov/nis2/src/branch/main/project-tasks/p14-b-flink-rescaling-recovery.md).

## Вопрос проекта

Сохраняется ли правильность обработки при восстановлении и изменении параллелизма?
Как размер состояния влияет на паузу обработки и время восстановления?

## Технический путь

Используем Apache Flink 2.3.0 через PyFlink.

Покупка содержит `event_id`, `user_id`, `amount_cents`.
[job.py](../job.py) хранит количество покупок и сумму по `user_id` в двух ValueState.
[check.py](../check.py) независимо рассчитывает ожидаемые итоги по исходному входу.

## Ожидаемые результаты

| Результат | Как проверяем |
|---|---|
| Повторяемый источник и конвейер с состоянием | Повторный запуск дает те же покупки и итоговые агрегаты |
| Восстановление с прежним и измененным параллелизмом | После запуска из снимка `check.py` не обнаруживает пропусков, дубликатов и ошибок |
| Автоматизация сценариев | Скрипт сохраняет состояние, останавливает и восстанавливает задание, проверяет результат и записывает метрики |
| Сравнение трех размеров состояния | По три повтора каждой конфигурации, таблица измерений и графики |

## Сценарии

1. Непрерывная обработка контрольного входа с известным результатом.
2. Плановая остановка через savepoint при параллелизме 2 и продолжение при параллелизме 2.
3. Такая же остановка и продолжение при параллелизме 4.
4. Проверка корректности после принудительной остановки TaskManager и восстановления из завершенного checkpoint.

Каждую серию экспериментов проведем на одной машине с локальной файловой системой.
JobManager и TaskManager запустим отдельными процессами.
Размер состояния меняем числом пользователей.

Параметры, метрики и порядок запусков: [план эксперимента](experiment-plan.md).
