# Контрольная точка 1

[Описание проекта](../project.md), [план эксперимента](../experiment-plan.md).
Окружение и общие команды запуска: [README](../../README.md#окружение).

Проверены запуски с нуля. Восстановление и rescaling еще не проверялись.

## Малый пример

Параметры: `INPUT_PATH=data/purchases.jsonl`, `RUN_NAME=demo`, `PARALLELISM=2`.
Для повторения выберите тот же вход и новое `RUN_NAME` в `.env`.
Из корня репозитория:

```sh
python job.py
python check.py
```

В [контрольных данных](../../data/purchases.jsonl) восемь покупок. Ожидаемые итоги:

| Пользователь | Количество | Сумма |
|---|---:|---:|
| 101 | 3 | 3500 |
| 202 | 3 | 5000 |
| 303 | 2 | 750 |

Получено: [check.py](../../check.py) вернул `ok: true`, ошибок не обнаружено.

## Пробный запуск

Вход: 100 000 покупок трех пользователей, полученных повторением малого примера
с уникальными идентификаторами.
Параметры: `INPUT_PATH=data/purchases-large.jsonl`, `RUN_NAME=large`,
параллелизм 2, интервал checkpoint 1000 мс.
Выполнены `python job.py` и `python check.py`.

Ожидание: все 100 000 покупок обработаны без пропусков, дубликатов и ошибок.
Получено: `check.py` вернул код 0 и `ok: true`.
Время задания из `output/large/run.json`: 5226 мс
(при параллелизме 1: 5635 мс). Оба варианта прошли `check.py` без ошибок.
Выполнено по одному запуску для каждого параллелизма.

Во время работы команда `rg --files --hidden output/checkpoints` обнаружила
файл `chk-1/_metadata`. После завершения этого запуска в его каталоге
остались только пустые папки.

## Настраиваемый генератор

[generate.py](../../generate.py) проверен с `USER_COUNT=1000` и
`PURCHASES_PER_USER=100`: получено 100 000 покупок. Вход записан в
`data/generated/purchases.jsonl`, результат Flink в `output/generated/`.
Команды запуска: [README](../../README.md#контрольный-запуск).

Время задания: 30 539 мс при параллелизме 2. `check.py` вернул `ok: true`,
ошибок не обнаружено.

Также проверены вложенный путь, четыре покупателя по три покупки,
уникальность идентификаторов, повторяемость файла и отказ при нулевых параметрах.

## Окружение проверок

Проверенные версии: Python 3.12.10, Java 17.0.12. Flink 2.3.0 и остальные
Python-зависимости закреплены в [requirements.txt](../../requirements.txt).

Команды проверки версий:

```sh
python --version
java -version
```

Локальные запуски выполнены через MiniCluster. Конфигурацию на 100 000 пользователей
и отдельные процессы JobManager и TaskManager еще нужно проверить.

## Доступность данных метрик

| Метрики | Что подтверждено | Что осталось проверить |
|---|---|---|
| Пропуски, дубликаты, ошибки агрегатов | Есть отчеты `check.py` для малого и больших входов | Проверить результат после восстановления |
| Размер сохранения | Найдены файлы checkpoint | Получить сохраняемый savepoint и измерить размер в байтах |
| Пауза, восстановление, throughput | Измерено только время задания | Собрать журнал команд и событий с временными отметками |

Определения и способы расчета: [план эксперимента](../experiment-plan.md#метрики).

## Риски и следующие шаги

1. Добавить журнал обработки и команд, проверить расчеты временных метрик на пробном запуске.
2. Подготовить отдельные процессы Flink и сценарий остановки и восстановления.
   При восстановлении сохранить выходной каталог и UID; текущий `job.py` пока
   запрещает существующий каталог и не принимает путь снимка.
3. Проверить получение сохраняемого savepoint, его размер и восстановление после сбоя.
4. Проверить верхнюю конфигурацию по памяти и длительности, затем зафиксировать
   параметры основных серий.
