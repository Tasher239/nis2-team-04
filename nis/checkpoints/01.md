Параметры: `INPUT_PATH=data/purchases.jsonl`, `RUN_NAME=demo`, `PARALLELISM=2`.
Для повторения выберите тот же вход и новое `RUN_NAME` в `.env`.
Из корня репозитория:

```sh
python job.py
python check.py
```

В [контрольных данных](../../data/purchases.jsonl) восемь покупок. Ожидаемые итоги:

| Пользователь | Количество | Сумма |
|---|---:|---:|
| 101 | 3 | 3500 |
| 202 | 3 | 5000 |
| 303 | 2 | 750 |

Получено: [check.py](../../check.py) вернул `ok: true`, ошибок не обнаружено.

## Пробный запуск

Вход: 100 000 покупок трех пользователей, полученных повторением малого примера
с уникальными идентификаторами.
Параметры: `INPUT_PATH=data/purchases-large.jsonl`, `RUN_NAME=large`,
параллелизм 2, интервал checkpoint 1000 мс.
Выполнены `python job.py` и `python check.py`.

Ожидание: все 100 000 покупок обработаны без пропусков, дубликатов и ошибок.
Получено: `check.py` вернул код 0 и `ok: true`.
Время задания из `output/large/run.json`: 5226 мс
(при параллелизме 1: 5635 мс). Оба варианта прошли `check.py` без ошибок.
Выполнено по одному запуску для каждого параллелизма.

Во время работы команда `rg --files --hidden output/checkpoints` обнаружила
файл `chk-1/_metadata`. После завершения этого запуска в его каталоге
остались только пустые папки.

`PURCHASES_PER_USER=100`: получено 100 000 покупок. Вход записан в
`data/generated/purchases.jsonl`, результат Flink в `output/generated/`.
Команды запуска: [README](../../README.md#контрольный-запуск).

ошибок не обнаружено.

Также проверены вложенный путь, четыре покупателя по три покупки,
уникальность идентификаторов, повторяемость файла и отказ при нулевых параметрах.

### Как запускать metrics.py вместе с остальными этапами

Все команды выполняем из корня репозитория. Один раз подготовьте окружение
по [README](../../README.md#окружение). В новом терминале активируйте его:

```sh
source .venv/bin/activate
export JAVA_HOME=$(/usr/libexec/java_home -v 17)  (mac)
export PATH="$JAVA_HOME/bin:$PATH"  (mac)
```

В `.env` задайте вход и имя запуска, например:

```ini
INPUT_PATH=data/generated/purchases.jsonl
USER_COUNT=1000
PURCHASES_PER_USER=100
RUN_NAME=metrics-demo-01
PARALLELISM=2
```

Остальные параметры `.env` оставьте как есть. Затем выполните по очереди:

```sh
python generate.py
python job.py
python check.py
python metrics.py output/metrics-demo-01
```

`metrics.py` читает журнал из указанной папки и выводит расчет метрик
в терминал. Путь передается явно: сам `metrics.py` не читает `RUN_NAME`
из `.env`. Если имя запуска другое то надо поменяьт путь в команде.

После `job.py` в папке запуска лежат:

| Файл | Что в нем |
|---|---|
| `part-*` (могут быть во вложенных папках) | Обработанные покупки, накопленные итоги и `processed_at_ns` - время обработки каждой покупки |
| `commands.jsonl` | Время вызова `env.execute` и время его успешного завершения |
| `run.json` | Идентификатор задания, время работы Flink, параллелизм и путь к checkpoint |


Отчет `metrics.json`:

| Поле | Что означает |
|---|---|
| `processed_records` | Сколько записей прочитано из результата |
| `pause_s` | Пауза между последним событием до остановки и первым после восстановления, в секундах |
| `recovery_s` | Время от команды восстановления до первого нового события, в секундах |
| `throughput_window_s` | Длина окна измерения скорости: 10 секунд |
| `events_in_window` | Сколько событий попало в это окно |
| `window_complete` | Достаточно ли времени прошло до завершения задания для полного окна |
| `throughput_events_s` | Число событий в окне, деленное на 10, либо `null` для короткого запуска |

При обычном запуске с нуля `pause_s` и `recovery_s` равны `null`:
тк восстановления не было.
